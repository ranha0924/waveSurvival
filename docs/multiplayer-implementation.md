# 협동 멀티플레이 — 구현 노트 (M1 + M2 + M3)

설계 문서(`multiplayer-coop-design.md`)의 **M0 + M1 + M2 + M3**를 구현했습니다.

- **M1**: 여러 명이 한 방에 들어와 같은 맵에서 서로를 보고, 같은 적을 함께 잡기.
- **M2**: 적이 **모든 플레이어를 타깃팅** → 게스트도 실제로 피격·사망. 죽으면
  **관전(downed)** 상태로 대기하다 다음 웨이브에 **자동 부활**.
- **M3**: ① 웨이브 클리어 시 **각자 개인 업그레이드 카드** 선택(전원 선택 시 다음
  웨이브 시작), ② **콤보/굿판 개인 귀속**(자기 킬로 자기 콤보·굿판 발동, 점수는
  팀 공동), ③ **호스트가 죽어도 세션 유지** — 호스트도 게스트처럼 관전하고, **전원
  다운 시에만** 진짜 게임오버.

## 채택한 모델: 릴레이 서버 + 호스트 권위

`enemy.js`를 Node로 포팅하는 대규모 작업을 피하기 위해, 설계 문서 §3.1의
**"릴레이 + 호스트 권위(host-authority over a dumb relay)"** 모델을 골랐습니다.

- **서버**(`server/index.js`)는 순수 릴레이입니다. 방 관리 + 메시지 중계만 하고,
  적/웨이브/데미지를 시뮬레이션하지 않습니다. (~180줄)
- **호스트**(방 첫 입장자)는 기존 싱글플레이 시뮬을 **그대로** 자기 브라우저에서
  돌리고, 권위 월드 스냅샷을 ~20Hz로 방송합니다.
- **게스트**는 적을 시뮬레이션하지 않습니다. 호스트 스냅샷을 렌더하고, 자기
  플레이어만 로컬에서 움직이며, 사격 시 **히트를 호스트에 보고**하면 호스트가
  데미지를 적용(권위)합니다.
- 모든 클라이언트가 자기 **플레이어 상태**를 ~25Hz로 방송 → 서로를 빌보드로 표시.

싱글플레이 경로는 `MP.active === false`일 때 **바이트 단위로 동일**합니다. 모든
멀티 코드는 그 플래그 뒤에 게이트되어 있습니다.

## 추가/변경된 파일

| 파일 | 내용 |
|------|------|
| `server/index.js`, `server/package.json` | 릴레이 WebSocket 서버 (의존성: `ws`) |
| `js/net.js` | WebSocket 트랜스포트(연결, JSON 송수신, 핑/지연 측정) |
| `js/multiplayer.js` | 협동 코디네이터 — 역할/방/원격 플레이어/스냅샷/보간 |
| `js/main.js` | 루프에 `MP.beginFrame`/`endFrame`, 게스트는 적 시뮬 스킵, 적 `netId` 부여, 로비 배선 |
| `js/player.js` | 게스트의 `damageEnemy`는 로컬 변경 대신 `MP.reportHit`; `damageEnemy` export |
| `js/raycaster.js` | 원격 플레이어를 깊이 정렬 빌보드로 렌더(`drawRemotePlayer`) |
| `index.html`, `style.css` | "👥 협동" 로비 오버레이 + 스크립트 로드 |

## 로컬에서 실행하기

```bash
# 1) 릴레이 서버 띄우기
cd server
npm install
npm start            # → :8787 에서 대기 (PORT 환경변수로 변경 가능)

# 2) 게임을 정적 서버로 호스팅 (브라우저 2개로 테스트)
cd ..
npx serve .          # 또는 python3 -m http.server 8080
```

- 브라우저 탭 A: 게임 열기 → **👥 협동** → 서버 `ws://localhost:8787`,
  방 코드 `GUT1` → **입장** (이 탭이 방장 = 호스트)
- 브라우저 탭 B(또는 다른 기기): 같은 방 코드 `GUT1`로 **입장** (게스트)
- 두 탭에서 서로의 캐릭터가 맵에 보이고, 같은 적을 함께 잡을 수 있습니다.

## 배포 (서버 호스팅)

`server/`는 어디든 올릴 수 있는 표준 Node 앱입니다.

- **Render / Railway / Fly.io 무료 티어** 권장: 레포의 `server/` 디렉터리를
  배포, start 커맨드 `node index.js`, 포트는 `PORT` 환경변수 자동 주입.
- 배포 후 게임의 로비 "서버 주소"에 `wss://<your-app>.onrender.com` 입력
  (HTTPS 페이지에서는 반드시 `wss://`).

## M2에서 추가된 것 (다중 타깃 + 게스트 피격/관전/부활)

- **적의 다중 타깃 어그로**: 호스트 적 AI가 `MP.getAllPlayers()`로 호스트 + 생존
  게스트 목록을 얻어, 각 적이 **최근접 가시 플레이어**를 추격/공격합니다
  (`enemy.js`의 `targetablePlayers` / `pickTarget`). 시그니처는 그대로라 싱글
  플레이는 무변경.
- **게스트 피격**: 적이 게스트를 때리면 호스트가 `{ev:hurt, to:게스트, dmg}`를
  보내고, 해당 게스트만 자기 HP에 적용(`MP.damageRemotePlayer` ↔ `ev` 핸들러).
  데미지 권위는 호스트 유지.
- **관전 후 부활**: 게스트 HP가 0이 되면 게임오버 대신 `downed`(관전) 상태로
  전환 — hp 0이라 어그로에서 자동 제외. 호스트가 다음 웨이브를 시작해 월드
  스냅샷의 wave 번호가 오르면 게스트가 자동 부활(HP 회복). 쓰러진 동료는 화면에
  흐리게 표시됩니다.

## M3에서 추가된 것 (개인 카드 + 콤보 귀속 + 호스트 관전)

- **개인 업그레이드 카드 (전원 선택 대기)**: 호스트가 웨이브를 클리어하면
  `{ev:wave_clear}`를 방송. 각 클라가 **자기 메뉴**를 띄워 독립적으로 한 장 선택해
  자기 플레이어에 적용하고 `{ev:picked}`를 호스트에 보고. 호스트는 **연결된 전원이
  선택**(또는 30초 타임아웃)하면 `{ev:wave_start}`를 방송하고 다음 웨이브를 시작.
  카드 풀은 각자 로컬에서 뽑으므로(서로 달라도 무방) 시드 동기화 불필요.
- **콤보/굿판 개인 귀속, 점수는 팀 공동**: 게스트의 막타로 적이 죽으면 호스트가
  `{ev:kill, to:게스트}`를 보내 게스트가 **자기 콤보를 직접 증가**(`Player.registerKill`)
  → 자기 굿판이 발동하고 자기 사격이 버프됨. 팀 점수는 호스트 권위로 유지하되,
  게스트 킬의 점수 배수는 히트 보고에 실린 게스트 콤보/굿판으로 계산
  (`damageEnemy`의 `attacker` 파라미터). 호스트 자기 콤보는 오염되지 않음.
- **호스트 사망 = 관전 (세션 유지)**: 호스트도 죽으면 게스트처럼 `downed`가 되지만
  **시뮬/방송은 계속**합니다(시뮬 권위와 플레이어 생사 분리). 생존한 사람이 적을
  잡아 웨이브를 넘기면 전원 부활. **전원 다운 시에만** 호스트가 `{ev:gameover}`를
  방송해 모두 함께 게임오버.

> ⚠️ 구현 중 `multiplayer.js`의 `isHost()`/`isGuest()`가 export 프로퍼티로만
> 존재하고 내부 함수로 정의돼 있지 않던 버그를 발견·수정했습니다(내부 호출이 전부
> 터지던 문제 — M1부터 잠재). 네트워크 로직은 노드 하니스로 단위 검증했지만, 실제
> 2-브라우저 플레이 검증은 아직 필요합니다.

## 아직 남은 것 (M4+)

- **호스트 연결 끊김 = 세션 종료**: 호스트가 죽는 것은 괜찮지만, 호스트가 **탭을
  닫으면**(연결 종료) 시뮬이 사라져 방이 닫힙니다(`host_left`). 호스트 마이그레이션은
  후순위.
- 인원 비례 적 스케일링, 보스 컷씬 게스트 공유, 보간 버퍼(현재는 지수 스무딩),
  바이너리 직렬화.

## 프로토콜 (현재 구현)

```jsonc
// 클라 → 서버
{ "t": "join", "room": "GUT1", "name": "무당", "seed": 12345 }
{ "t": "pstate", "x": 21.4, "y": 19.8, "a": 1.57, "hp": 90 }   // 자기 플레이어
{ "t": "hit", "id": 11, "dmg": 30, "head": true, "combo": 4, "gut": 1 }  // 게스트→호스트(M3: combo/gut)
{ "t": "world", ... }                                          // 호스트 스냅샷
{ "t": "ping", "ts": 123 }

// 이벤트(ev) — 서버가 방 멤버에게 릴레이, 수신측이 k/to로 필터
{ "t": "ev", "k": "hurt",       "to": "p2", "dmg": 15 }        // 호스트→게스트: 피해(M2)
{ "t": "ev", "k": "kill",       "to": "p2", "head": false, "boss": false } // 호스트→게스트: 네 막타(M3)
{ "t": "ev", "k": "wave_clear", "wave": 3 }                   // 호스트→전체: 업그레이드 메뉴 열기(M3)
{ "t": "ev", "k": "picked",     "wave": 3 }                   // 게스트→호스트: 카드 선택 완료(M3)
{ "t": "ev", "k": "wave_start", "wave": 4 }                   // 호스트→전체: 다음 웨이브 시작(M3)
{ "t": "ev", "k": "gameover" }                               // 호스트→전체: 전원 다운(M3)

// 서버 → 클라 (relay + 서버 자체 메시지)
{ "t": "hello", "id": "p1" }
{ "t": "welcome", "id": "p2", "room": "GUT1", "isHost": false, "seed": 12345, "players": [...] }
{ "t": "peer_join" | "peer_leave" | "roster", ... }
{ "t": "host_left" }   // 방장 이탈 → 세션 종료
// world 스냅샷 본문:
{ "t": "world", "enemies": [{ "id":11,"t":"grunt","x":..,"y":..,"hp":18,"mhp":30,"hop":0,"fl":0 }],
  "proj": [{ "x":..,"y":.. }], "wave": 3, "alive": 7, "score": 2500 }
```
