# 협동 멀티플레이 — 구현 노트 (M1 + M2)

설계 문서(`multiplayer-coop-design.md`)의 **M0 + M1 + M2**를 구현했습니다.

- **M1**: 여러 명이 한 방에 들어와 같은 맵에서 서로를 보고, 같은 적을 함께 잡기.
- **M2**: 적이 **모든 플레이어를 타깃팅** → 게스트도 실제로 피격·사망. 게스트가
  죽으면 **관전(downed) 상태로 대기**하다 호스트가 다음 웨이브를 시작하면 **자동
  부활**.

## 채택한 모델: 릴레이 서버 + 호스트 권위

`enemy.js`를 Node로 포팅하는 대규모 작업을 피하기 위해, 설계 문서 §3.1의
**"릴레이 + 호스트 권위(host-authority over a dumb relay)"** 모델을 골랐습니다.

- **서버**(`server/index.js`)는 순수 릴레이입니다. 방 관리 + 메시지 중계만 하고,
  적/웨이브/데미지를 시뮬레이션하지 않습니다. (~180줄)
- **호스트**(방 첫 입장자)는 기존 싱글플레이 시뮬을 **그대로** 자기 브라우저에서
  돌리고, 권위 월드 스냅샷을 ~20Hz로 방송합니다.
- **게스트**는 적을 시뮬레이션하지 않습니다. 호스트 스냅샷을 렌더하고, 자기
  플레이어만 로컬에서 움직이며, 사격 시 **히트를 호스트에 보고**하면 호스트가
  데미지를 적용(권위)합니다.
- 모든 클라이언트가 자기 **플레이어 상태**를 ~25Hz로 방송 → 서로를 빌보드로 표시.

싱글플레이 경로는 `MP.active === false`일 때 **바이트 단위로 동일**합니다. 모든
멀티 코드는 그 플래그 뒤에 게이트되어 있습니다.

## 추가/변경된 파일

| 파일 | 내용 |
|------|------|
| `server/index.js`, `server/package.json` | 릴레이 WebSocket 서버 (의존성: `ws`) |
| `js/net.js` | WebSocket 트랜스포트(연결, JSON 송수신, 핑/지연 측정) |
| `js/multiplayer.js` | 협동 코디네이터 — 역할/방/원격 플레이어/스냅샷/보간 |
| `js/main.js` | 루프에 `MP.beginFrame`/`endFrame`, 게스트는 적 시뮬 스킵, 적 `netId` 부여, 로비 배선 |
| `js/player.js` | 게스트의 `damageEnemy`는 로컬 변경 대신 `MP.reportHit`; `damageEnemy` export |
| `js/raycaster.js` | 원격 플레이어를 깊이 정렬 빌보드로 렌더(`drawRemotePlayer`) |
| `index.html`, `style.css` | "👥 협동" 로비 오버레이 + 스크립트 로드 |

## 로컬에서 실행하기

```bash
# 1) 릴레이 서버 띄우기
cd server
npm install
npm start            # → :8787 에서 대기 (PORT 환경변수로 변경 가능)

# 2) 게임을 정적 서버로 호스팅 (브라우저 2개로 테스트)
cd ..
npx serve .          # 또는 python3 -m http.server 8080
```

- 브라우저 탭 A: 게임 열기 → **👥 협동** → 서버 `ws://localhost:8787`,
  방 코드 `GUT1` → **입장** (이 탭이 방장 = 호스트)
- 브라우저 탭 B(또는 다른 기기): 같은 방 코드 `GUT1`로 **입장** (게스트)
- 두 탭에서 서로의 캐릭터가 맵에 보이고, 같은 적을 함께 잡을 수 있습니다.

## 배포 (서버 호스팅)

`server/`는 어디든 올릴 수 있는 표준 Node 앱입니다.

- **Render / Railway / Fly.io 무료 티어** 권장: 레포의 `server/` 디렉터리를
  배포, start 커맨드 `node index.js`, 포트는 `PORT` 환경변수 자동 주입.
- 배포 후 게임의 로비 "서버 주소"에 `wss://<your-app>.onrender.com` 입력
  (HTTPS 페이지에서는 반드시 `wss://`).

## M2에서 추가된 것 (다중 타깃 + 게스트 피격/관전/부활)

- **적의 다중 타깃 어그로**: 호스트 적 AI가 `MP.getAllPlayers()`로 호스트 + 생존
  게스트 목록을 얻어, 각 적이 **최근접 가시 플레이어**를 추격/공격합니다
  (`enemy.js`의 `targetablePlayers` / `pickTarget`). 시그니처는 그대로라 싱글
  플레이는 무변경.
- **게스트 피격**: 적이 게스트를 때리면 호스트가 `{ev:hurt, to:게스트, dmg}`를
  보내고, 해당 게스트만 자기 HP에 적용(`MP.damageRemotePlayer` ↔ `ev` 핸들러).
  데미지 권위는 호스트 유지.
- **관전 후 부활**: 게스트 HP가 0이 되면 게임오버 대신 `downed`(관전) 상태로
  전환 — hp 0이라 어그로에서 자동 제외. 호스트가 다음 웨이브를 시작해 월드
  스냅샷의 wave 번호가 오르면 게스트가 자동 부활(HP 회복). 쓰러진 동료는 화면에
  흐리게 표시됩니다.

## 아직 남은 것 (M3+)

- **게스트의 업그레이드 카드**: 웨이브 클리어 시 업그레이드는 호스트만 받습니다.
  → 개인 빌드 동기화(설계 §7).
- **굿판/콤보 귀속**: 게스트의 막타는 호스트가 데미지를 적용하므로 게스트 콤보가
  쌓이지 않습니다. → 호스트가 "누가 막타를 쳤는지" 귀속 정보를 이벤트로 전달.
- **호스트 사망 = 세션 종료**: 호스트가 죽으면 시뮬/방송이 멈춥니다. 호스트
  마이그레이션은 후순위.
- 인원 비례 적 스케일링, 보간 버퍼(현재는 지수 스무딩), 바이너리 직렬화.
